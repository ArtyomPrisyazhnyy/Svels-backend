# Правила для агентов (Svels backend)

## Архитектура модулей

- Модули изолированы по домену: **без JOIN между модулями** в запросах и **без прямых импортов чужих сервисов**.
- Связь между модулями — через **токены DI**, **интерфейсы** и **события** (`@nestjs/event-emitter`).
- Идентификаторы сущностей — **UUID v7** (генерация через `UuidV7Subscriber` / `generateUuidV7()`).

## API и данные

- Глобальный `ValidationPipe`: `whitelist: true`, `forbidNonWhitelisted: true`, `transform: true`.
- **Не использовать raw SQL с интерполяцией** строк; только параметризованные запросы или TypeORM API.
- Транзакции и мульти-ключевые операции Redis — по правилам в `CacheService` (pipeline, locks).

## Тесты

- Новое поведение сопровождается **unit- и/или e2e-тестами**.
- Запуск: `npm test`, `npm run test:e2e`.
- Для линтинга изменённых файлов: `npx eslint <файлы>` **без** `--fix`. Команду `npm run lint` не запускать (она с `--fix`).

## Миграции БД

- Схема в проде — только через TypeORM migrations (`npm run migration:run`).
- `DB_SYNC=true` — только для осознанной локальной синхронизации, не для production.
- Новая миграция: **новый файл** `src/database/migrations/<timestamp>-<TaskId><Name>.ts`.
- **Существующие миграции не редактировать** после применения.

## Ограничения для автоматических правок

- Не менять зависимости и `package-lock.json` без явного запроса.
- Не коммитить `dist/`.
- Не переформатировать файлы, которые не меняются в задаче.
