# Роли сотрудников заведения

Владелец остаётся `restaurant_admin`. Новые роли — рабочие, без права найма и без владельческих настроек.

| Роль | Значение | Доступ |
|---|---|---|
| Владелец | `restaurant_admin` | всё, включая найм, эквайринг, домен, стилизацию |
| Управляющий | `restaurant_manager` | меню, график, зал, брони, заказы, маркетинг; **не** оплата, домен, сотрудники, брендинг |
| Зал / приём | `restaurant_hall` | брони и живые заказы |
| Производство | `restaurant_production` | очередь заказов |

Права задаются картой `RestaurantPermission` (`src/common/auth/restaurant-role-permissions.ts`). Эндпоинты помечаются `@StaffRoles(permission)` — RolesGuard получает уже развёрнутый список ролей.

Найм сотрудников (приглашение по телефону/email) в этой итерации **не** реализован: аккаунт с новой ролью можно создать только напрямую в БД / через внутренний `UsersService.create`. Приглашения — отдельная задача, только у владельца (`MANAGE_STAFF`).
